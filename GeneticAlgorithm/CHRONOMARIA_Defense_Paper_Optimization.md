## Section 3.4: Design and Implementation of the Optimization and Evaluation Framework

### 3.4.1 Pool-Based Schedule Generation Pipeline

The scheduling component of CHRONOMARIA was designed as a pool-based deterministic optimizer rather than a probabilistic or evolutionary search procedure. The central challenge it was built to address was the assignment of rooms and time intervals to a set of course offerings that each carried pre-declared scheduling preferences, in a manner that produced a conflict-free assignment while remaining fully traceable and reproducible. The decision to forgo a stochastic search at this stage was deliberate: administrators who oversee academic scheduling needed to understand and trust the assignment logic, and a rule-governed deterministic pipeline — one in which the same input consistently produced the same output — was better suited to that institutional requirement than a method whose results varied across runs. Course offerings were therefore treated as scheduling entities, each representing an atomic unit of work to which the pipeline would assign or protect a room-and-time coordinate, and the evaluation of competing claims over shared resources was governed by an explicit, ordered decision protocol rather than by chance.

Before any room assignment was attempted, CHRONOMARIA performed a preflight validation pass in which all incoming subject records were parsed, normalized, and classified. Each record was assigned one of two states — scheduled, if it already carried both a room identifier and a time-block assignment from a prior manual entry, or empty, if it had not yet been assigned either. Alongside state classification, the preflight stage constructed a RoomTypeRegistry by traversing the list of active rooms and cataloguing each room as either a laboratory or a lecture room; this registry was subsequently used throughout the pipeline to enforce type-compatibility constraints between subjects and their assigned rooms. Crucially, the preflight stage also established the foundational distinction between a merged subject and a scheduling conflict: two subject records that shared the same descriptive title, the same room, and the same time interval were recognized as co-located sections of the same course and were preserved as a single coherent group, never flagged as a violation. Only records carrying different descriptive titles that competed for the same room at the same time could constitute a genuine conflict, and this three-part definition governed all conflict detection logic in the stages that followed.

Once all entities had been classified, CHRONOMARIA grouped them into pools according to their room assignments, with each pool corresponding to a single room and containing every entity that had declared an assignment to that room. Within each pool, a designated set of locked entities — those preserved from the preflight stage as manually confirmed and immovable — served as anchor points against which all other entities were evaluated. A conflict detection predicate was applied pairwise across pool members: two entities were determined to conflict if and only if their scheduled time intervals overlapped on the same day, they occupied the same room, and they carried different descriptive titles. This three-part predicate — room identity, temporal overlap, and title difference — represented the hard constraint that defined illegality throughout the scheduling pipeline. Any entity whose interval overlapped with that of a locked anchor was immediately displaced to the conflicted set for downstream processing, ensuring that manually confirmed assignments were never disturbed by the resolution process that followed.

When two non-anchored entities within the same pool were found to conflict with one another, CHRONOMARIA resolved the dispute through a five-level priority key that functioned as the scoring mechanism of the scheduling pipeline — much like an adjudication panel consulted in a strict, predetermined order, where each judge was called upon only when the one before it could not decide. The priority key was evaluated as an ordered tuple in the following sequence: the entity with the greater total unit weight ranked first; among entities of equal unit weight, the one with the greater number of laboratory hours ranked next; if that dimension also produced a tie, the entity with more lecture hours was favoured; if still unresolved, the entity with the earlier scheduled start time was given precedence; and as a final tiebreaker, alphabetical ordering by subject code determined the outcome. The entity that ranked lower in this evaluation was not discarded from the system — it was transferred to a migration queue for placement in an alternate room and time slot, preserving its existence in the assignment process while freeing its contested slot for the higher-priority entity. This scoring mechanism encoded a coherent institutional value system directly into the resolution protocol: courses that carried greater academic weight, demanded more specialized resources, and began earlier in the day were systematically protected over lighter, later, or less resource-intensive ones.

For each entity transferred to the migration queue, CHRONOMARIA executed a migration cascade consisting of six progressively broader search stages, each representing an expansion of the candidate room set from which a new valid placement could be drawn. A subject requiring a laboratory room was restricted to laboratory rooms throughout all six stages, reflecting the scarcity of that resource and the inviolability of its type requirement; a lecture-only subject preferred lecture rooms as a first option but was permitted to accept a laboratory room as a fallback in later stages. Within each stage, the system enumerated candidate start times in thirty-minute increments across the scheduling window of 7:30 AM to 8:00 PM, automatically excluding any start time that would position a class wholly or partially within the protected midday window. A placement was accepted if and only if it produced no temporal overlap with any entity already settled in the target pool. Entities that exhausted all six stages without securing a valid placement were forwarded to the manual review queue rather than placed in a known-conflicting slot — a deliberate architectural choice that prioritized the integrity of the generated schedule over its completion rate.

Subjects that entered the pipeline without any prior room or time assignment were processed in a two-phase empty-field placement procedure that followed the migration cascade. In the first phase, subjects requiring laboratory rooms were processed before lecture-only subjects, because laboratory rooms represented the scarcer resource and their early allocation reduced the likelihood that a lab-dependent subject would be left without a valid assignment. In the second phase, lecture-only subjects were placed into lecture rooms as a first preference, with laboratory rooms available as an overflow option when no lecture room could accommodate them. Both phases applied the same five-level priority key used during conflict arbitration, ensuring that heavier, more resource-intensive subjects claimed time slots before lighter ones and that the order of placement was never arbitrary. Subjects belonging to the PathFit physical education category were subject to an additional hard rule throughout both phases: they were exclusively confined to gymnasium rooms, and no gymnasium room was permitted to host more than three simultaneously scheduled sections drawn from the same department at any given time interval. Upon the conclusion of all placement phases, CHRONOMARIA performed a final conflict scan over the complete set of placed entities; any residual violations detected at this late stage were removed from the placed set, forwarded to the manual review queue, and recorded in a diagnostic report that was returned to the calling process alongside the primary schedule output.

The quality of the generated schedule was quantified through a soft fitness function that operated in two tiers distinguished by the categorical severity of the constraints they represented. Any solution in which even a single entity violated a hard constraint — which encompassed room double-booking, section time overlap, breach of the 7:30 AM to 8:00 PM scheduling boundary, violation of the PathFit-to-gymnasium rule, or gymnasium overcrowding beyond the same-department simultaneous threshold — received a fitness value of negative infinity and was excluded from any further consideration entirely, regardless of how well it performed on all other dimensions. For solutions that satisfied every hard constraint, a soft penalty value was accumulated from several sources of preference violation: placement of a subject in a room of an incompatible type contributed a weighted penalty proportional to the severity of the mismatch, with the penalty scaled differently depending on whether a lecture subject had been assigned to a laboratory room or a laboratory subject had been assigned to a non-laboratory room; a preference for scheduling classes early in the day was encoded as a proportional penalty on the delay between a subject's assigned start time and the earliest valid slot, capturing the institutional preference for morning-heavy timetables; an imbalance between the number of subjects assigned to the Monday–Thursday pattern and those assigned to the Tuesday–Friday pattern within a section incurred an incremental penalty for each unit of imbalance; and a section that accumulated an excessive volume of classes within a single calendar day contributed a further penalty when that daily density exceeded comfortable pedagogical norms. The soft fitness was then computed according to the expression `soft_score = max(0, 100 − (soft_penalty / n_subjects) × 5.0)`, where dividing the accumulated penalty by the total number of subjects normalized the result across scheduling instances of different sizes, preventing larger timetables from being systematically disadvantaged relative to smaller ones simply by virtue of having more courses. The resulting soft score was a quality index on the interval zero to one hundred that expressed, in a single value, how faithfully the generated schedule honoured institutional preferences — after all absolute structural rules had already been satisfied.

---

The pool-based scheduling pipeline described in the preceding subsection established the fixed time-slot and room coordinates for every course offering in the academic term. These coordinates were not incidental outputs — they became the immovable structural scaffolding on which the faculty loading optimization was subsequently built. Assigning a faculty member to a course offering without knowing when and where that offering was scheduled would have made it impossible to verify whether the proposed assignment introduced a time conflict between two of that faculty member's concurrent obligations, or placed two courses in the same room at overlapping times. The Genetic Algorithm for faculty loading was therefore designed to receive the scheduler's placement output as a prerequisite input, and every constraint evaluation it performed operated against the time blocks and room identifiers that the scheduling pipeline had already locked into place.

### 3.4.2 Genetic Algorithm for Faculty Loading

The faculty loading optimization in CHRONOMARIA was implemented as a classical Genetic Algorithm in which each candidate solution was encoded as a chromosome — a fixed-length integer array in which every position, or gene locus, corresponded to one course offering and the integer value stored at that locus represented the index of the faculty member assigned to that offering. This encoding was deliberately compact: it reduced each complete assignment plan to a sequence of integers that could be manipulated by standard evolutionary operators without risk of producing a structurally invalid solution. Population initialization proceeded in two phases. In the first phase, faculty members who had been explicitly tagged with a Priority 1 (High) subject preference by a department coordinator were pre-assigned to their designated offerings before any evolutionary operator was applied; these assignments were embedded into every member of the initial population as frozen loci, guaranteeing that explicit human decisions made outside the algorithm were never overwritten by the random variation of early generations. In the second phase, the remainder of the initial population was constructed by first building a single greedy base chromosome — selecting for each offering the highest-scoring eligible faculty member available at the moment of assignment — and then applying diversifying mutations to that base to produce the required population size, ensuring sufficient initial variety for the evolutionary search to explore meaningfully.

The process by which eligible faculty members were identified and ranked for each course offering was one of the most structurally detailed components of the CHRONOMARIA system and operated through a three-pass selection mechanism that was more analogous to a hierarchical hiring committee than to a uniform random draw from an undifferentiated pool. In Pass A, the system assembled a candidate set from any faculty member whose academic specialization was judged to match the offering in question, either through an explicit preference tag or through a phrase-based similarity measure applied against the subject's descriptive title, course code, and course number; same-department candidates were always included in this pass, while cross-department candidates were admitted only when they held a Priority 1 preference tag, reflecting the institutional position that unsolicited cross-departmental assignments should require the strongest possible endorsement. If Pass A yielded no eligible candidates, the system fell back to Pass B, which considered all faculty members within the same department as the offering regardless of whether a specialization match had been established. A narrow additional exception, Pass C, permitted Information Technology faculty to cover Computer Science offerings in circumstances where the Computer Science department had no active faculty records of its own. Once a candidate set had been assembled through whichever pass produced results, each candidate received a composite score: the candidate's specialization score was multiplied by 1.0 if the assignment remained within the same department, or discounted to a factor of 0.65 if it crossed departmental boundaries; a bonus of 120 points was added for full-time faculty members or 45 for part-time members to reflect their different institutional relationships with the timetable; and the product of the faculty member's current usage ratio and 150 was subtracted as a load-balancing penalty. This formulation encoded equitable distribution directly within the selection pressure: a heavily loaded full-time faculty member could be outscored by a lighter-loaded part-time member when the difference in workload was large enough to outweigh the employment-type bonus, ensuring that the algorithm did not simply concentrate all offerings on the most qualified or most senior individuals. The specialization score that entered this formula was itself the product of a layered matching process that prioritized explicit human guidance over algorithmic inference. When a faculty member had been tagged by a coordinator at any of three priority levels, that tag took absolute precedence over all other matching signals: a Priority 1 designation returned a specialization score of 100, Priority 2 returned 50, and Priority 3 returned 15. In the absence of any explicit preference tag, the system computed a phrase-normalized matching score by comparing the faculty member's recorded specialization phrases against the offering's descriptive title at a contribution weight of 24, against the subject code at a weight of 16, and against the course number at a weight of 14. Matching was evaluated bidirectionally — both the faculty phrase was tested for containment within the subject text and the subject text for containment within the faculty phrase — and comparisons operated on normalized strings from which stop words and domain-generic academic vocabulary had been removed, reducing the risk that common terms would produce spurious high-confidence matches between unrelated specializations.

The fitness of each chromosome in the population was evaluated through a two-component function whose components were combined as a weighted sum expressed as `overall = hard × 0.72 + soft × 0.28`, reflecting the institutional judgment that constraint satisfaction was substantially more important than preference optimization while still acknowledging that preference quality was not negligible. The hard fitness component was formulated around a coverage score rather than a flat per-violation penalty structure. Coverage was defined as the proportion of course offerings that had received a faculty assignment, expressed as `coverage_score = 100 × (assigned / total_offerings)`, and the hard fitness was derived as `hard = max(0, coverage_score − hard_penalty)`, where the hard penalty accumulated from four categories of violation. Exceeding a faculty member's maximum permitted unit load incurred a penalty of 12.0 points per excess unit, reflecting the administrative severity of an overloaded appointment. A time conflict — two offerings assigned to the same faculty member with overlapping scheduled time blocks on the same day — incurred a penalty of 9.0 points per detected collision. Scheduling a faculty member for more than four consecutive teaching hours on a single day incurred a penalty of 7.0 points per affected day, reflecting both physiological limits on sustained instruction and accreditation standards for faculty workload. A room double-booking — two separate offerings assigned to the same room during overlapping time intervals — incurred a penalty of 9.0 points per occurrence. The coverage-based formulation of the hard fitness was architecturally significant: it preserved a meaningful fitness gradient across partially-assigned solutions, ensuring that a chromosome covering eighty percent of offerings was measurably fitter than one covering sixty percent even when both contained the same number of constraint violations, a property that a flat penalty structure would have obscured by collapsing solutions with different coverage levels to identical scores. The soft fitness component operated over the interval zero to one hundred and was expressed as `soft = max(0, min(100, 100 − soft_penalty + soft_bonus))`. Bonuses were awarded according to assignment quality: a same-department assignment confirmed by specialization match received a bonus of 12.0 points; a same-department assignment without a confirmed specialization match received 7.0 points; a cross-department assignment with a confirmed specialization match received 4.0 points; and all remaining assignments received a baseline of 1.0 point. The load imbalance among assigned faculty members was penalized quadratically, so that concentrating teaching load on a small number of individuals was penalized far more harshly than an equivalent total deviation distributed evenly across the faculty body — a quadratic term rather than a linear one precisely because the harm of extreme concentration grows non-linearly with its magnitude. Full-time faculty members were treated as a positive contribution to the soft component, with each full-time assignment reducing the accumulated soft penalty by 9.0 points, reflecting the institutional preference for deploying permanent faculty on regular course offerings before resorting to part-time appointments.

In each generation of the evolutionary loop, the entire population was evaluated through the fitness function and ranked in descending order of overall fitness. A defined fraction of the highest-scoring chromosomes — the elite individuals — were carried forward into the next generation without alteration, preserving the best solutions found so far and preventing the evolutionary process from inadvertently destroying high-quality assignments through unconstrained variation. The remaining population slots were filled by generating offspring through uniform crossover between pairs selected from the elite set, followed by point mutation applied at a configurable rate to introduce variation at individual gene loci. Positions in the chromosome that corresponded to manually confirmed assignments or to Priority 1 pre-assigned offerings were treated as frozen loci: neither the crossover operator nor the mutation operator was permitted to alter the values stored at these positions, ensuring that explicit coordinator decisions survived the entire evolutionary process intact and arrived unchanged in the final output. The Genetic Algorithm terminated under whichever of three conditions occurred first: the global time budget allocated to the optimization run was exhausted; the best fitness value present in the population had not improved for forty or more consecutive generations, a condition referred to as stagnation and interpreted as evidence that the search had converged to a local optimum from which further random variation was unlikely to escape; or the best fitness in the population reached or exceeded 99.5, a threshold that the system treated as a practically optimal solution beyond which additional computation was unlikely to yield a meaningfully better result.

The two optimization pipelines of CHRONOMARIA were designed not as independent systems but as a coherent evaluation hierarchy in which the output of the first pipeline constituted the immovable constraint environment of the second. The pool-based scheduler enforced structural correctness absolutely, ensuring that no schedule entered the faculty loading phase with an embedded room double-booking, section time overlap, boundary violation, or PathFit misassignment already present. The Genetic Algorithm for faculty loading then operated within that structurally verified space, using its coverage-based hard fitness to ensure that solutions with different numbers of assigned offerings remained distinguishable by natural selection regardless of their violation counts, and using its soft fitness to reward specialization alignment, workload equity, and institutional employment preferences at every generation. Together, the two evaluation mechanisms formed a coherent quality framework: structural correctness was enforced unconditionally by the scheduler, and optimality — in the sense of specialization fit, equitable load distribution, and adherence to institutional staffing preferences — was maximized by the evolutionary search. The result was a system that did not merely generate a schedule and a faculty loading plan, but could measure and explain the quality of what it produced, yielding a final output that was both verifiably correct and demonstrably optimal within the constraints and priorities of the institution it served.

### 3.4.3 Prior Evolutionary Scheduling Approach and Its Supersession

When CHRONOMARIA was first designed, the scheduling problem — assigning a room and a time slot to each of several hundred course offerings simultaneously — was framed as a combinatorial optimization problem of the kind for which evolutionary computation is widely regarded as appropriate. A Genetic Algorithm was developed to explore this search space, built on the DEAP evolutionary computation framework and designed to evolve a population of complete schedule assignments across successive generations. The appeal of the approach lay in its flexibility: rather than prescribing the exact path by which a solution was constructed, the algorithm was permitted to discover high-quality assignments by iteratively recombining and modifying candidate solutions and retaining those that best satisfied the institution's scheduling constraints. The component was fully implemented, tested, and integrated into the early system architecture as the primary mechanism by which unscheduled subject records received their room-and-time coordinates.

Each candidate schedule in this system was encoded as a single chromosome — a list of genes, one per subject — in which each gene was a four-element tuple of the form (pattern_idx, start_min, day1_room_idx, day2_room_idx). The first field, pattern_idx, specified which of the two weekly repeating patterns the subject followed: a value of zero designated the Monday–Thursday pattern and a value of one designated the Tuesday–Friday pattern. The second field, start_min, encoded the scheduled start time as an integer number of minutes elapsed since midnight, bounded between 450 (7:30 AM) and 1200 (8:00 PM) in increments of thirty minutes — the granularity at which room availability was tracked across the institution. The third and fourth fields, day1_room_idx and day2_room_idx, held integer indices into the global list of active rooms, identifying the rooms assigned to the first and second days of the weekly pattern respectively. Subjects that had already been manually confirmed by a coordinator — locked entities — were excluded from the chromosome entirely; their existing room-and-time coordinates were instead registered in a set of pre-seeded constraint slots that the fitness function treated as immovable anchors, ensuring that the evolutionary process could never relocate a decision that a human administrator had already ratified.

The fitness of each chromosome was evaluated through a function that first screened the solution for hard constraint violations, assigning any chromosome that contained even a single such violation a fitness of negative infinity and thereby guaranteeing its elimination from subsequent selection. The hard constraints applied to the scheduler GA were identical in substance to those enforced by the pool-based architecture that later replaced it: no subject was permitted to be scheduled outside the 7:30 AM to 8:00 PM window; no two subjects could occupy the same room at overlapping times on the same day; no two subjects within the same section could be scheduled at overlapping times on the same day; PathFit physical education subjects were exclusively confined to gymnasium rooms while all other subjects were forbidden from using them; and the number of same-department sections simultaneously occupying any single gymnasium slot was capped at three. Chromosomes that satisfied all hard constraints were then scored by a soft fitness function that accumulated penalties for room type mismatches, late start times relative to the earliest available slot, imbalances in the Monday–Thursday and Tuesday–Friday distribution within each section, excessive gaps or unbroken instructional runs within a section's daily schedule, and uneven utilization across available rooms, with the total penalty normalized by the number of subjects to yield a quality score between zero and one hundred. The population was reproduced through a section-aware crossover operator in which the genes corresponding to all subjects within the same section were treated as an indivisible unit and swapped between two parent chromosomes as a group, with each section group subject to a fifty-percent swap probability; this design preserved the intra-section coherence of pattern and daily load that individual-gene crossover would have disrupted. Mutation was applied per gene at a rate of seven percent and took one of four forms selected uniformly at random: a pattern flip that toggled the assignment between the Monday–Thursday and Tuesday–Friday pattern; a start-time nudge that shifted the scheduled start forward or backward by one to three thirty-minute increments within the valid range; and either a day-one or day-two room substitution that replaced one of the two room assignments with a fresh selection from the type-compatible room pool.

Following each generation of crossover and mutation, the best chromosome in the population was subjected to a post-GA Lamarckian repair operator that directly modified the gene values of any subject found to be involved in a hard constraint violation. Unlike Darwinian evolution, in which phenotypic fitness influences the probability of reproduction but the genome itself is not altered by the organism's experience, the Lamarckian repair operated by identifying all violating subjects, temporarily removing their occupancy from the room-and-section slot tracking structures, and then re-placing each violator through a greedy sequential search that enumerated valid patterns, start times, and room pairs until a conflict-free placement was secured or the per-pass time limit was reached. This repair procedure executed for up to five passes or until the allocated time budget was consumed, with each pass beginning from the state established by its predecessor. The initial population was assembled as a combination of a single greedy seed chromosome — in which subjects were processed in descending order of scheduled duration and each was placed in the first available conflict-free slot — and a set of randomly initialized chromosomes generated to fill the remainder of the target population size of one hundred and twenty. Within the evolutionary loop, the top twenty-five percent of each ranked generation was carried forward to the next generation as elite individuals, preserved without alteration to prevent the loss of high-quality solutions through random variation. The remaining population slots were filled by applying crossover and mutation to pairs drawn from that elite set. The loop terminated under whichever of three conditions was first satisfied: the global time budget was exhausted; the best fitness in the population had failed to improve for forty consecutive generations, a condition interpreted as convergence to a local optimum; or the best fitness reached or exceeded 99.5, a threshold treated as a practically optimal result.

Despite the completeness and technical correctness of the evolutionary scheduling implementation, the system was replaced prior to production deployment in favour of the pool-based deterministic architecture described in Section 3.4.1. The root cause of this architectural decision was a scalability limitation inherent in encoding the schedules of all course offerings — numbering several hundred in a full academic term — within a single chromosome. The resulting search space was too large for the GA to navigate reliably within the available time budget: runs on full-term datasets produced outputs that varied substantially across executions and frequently failed to converge on solutions of acceptable quality. More concretely, the system exhibited a census invariant violation in which the number of subjects present in the output was fewer than those provided as input, with individual subject records silently disappearing from the generated schedule without any diagnostic indication — a property wholly incompatible with the administrative accountability that institutional scheduling required. The pool-based deterministic architecture addressed both of these problems: by partitioning the scheduling problem at the room level, it reduced the scope of each individual conflict decision to the small set of subjects competing for a single room, eliminating the exponential scaling behavior that had degraded the GA's reliability; and by enforcing a coverage invariant at every stage of the pipeline, it guaranteed that every input subject was accounted for in the output, appearing either as a placed assignment or as an explicit entry in the manual review queue with a documented reason for its displacement. The evolutionary scheduling code was retained in the codebase as an archived component, its complete implementation serving both as a record of the design trajectory that was explored and as a foundation for potential future refinement of soft-objective optimization within individual room pools, should the system's scope expand to warrant a targeted evolutionary pass over each pool's internal arrangement.
